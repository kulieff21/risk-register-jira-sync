The register said Highest. Someone in Jira typed Low.

A GRC team keeps its risk register in Excel; the treatment work happens in Jira. This tool keeps the two consistent: every field has one owner, a hand edit on the wrong side is caught as drift before it is overwritten, and every write lands in an audit log with the value it replaced.

01 · the rule

Every field has exactly one owner. The owner’s value wins.

Two-way sync between a spreadsheet and a ticket system usually means “last write wins”, and nobody can say afterwards which number was true. Here the split is fixed in the design: the register owns what the risk is, Jira owns how the work is going.

Excel register owns

  • Summary[R-001] title
  • Descriptionasset, threat, scores, controls, plan
  • Priorityfrom inherent score
  • Due datetreatment deadline
  • Labelsgrc-risk, risk-*, treatment-*, ctrl-*
writes → ← reads

Jira issue owns

  • Statusread only
  • Resolution dateread only
  • Labels added by handkept, never removed

Status moves are normal work, not drift. “Done” is decided by the status category, not by the status name.

Found by label, not by titleEach risk’s issue carries the exact label risk-R-001. Renaming a risk does not create a second issue, and the register stores no Jira keys.
Drift is shown, then overwrittenA hand edit to a register-owned field appears in the dry run. On --apply the register wins and the audit log keeps the Jira value it replaced.
Never deletes, never picksTwo issues with the same risk label are a conflict: skipped and reported. An issue whose risk left the register is an orphan: reported, never closed.

03 · the gate

A broken register never reaches Jira.

Validation runs before every sync and collects all problems with their sheet row, not just the first one. This is examples/register-with-errors.xlsx, a test file with one mistake per row; the messages below are the tool’s actual output.

    05 · details

    The small decisions that make it safe to run twice.

    Each note links to the test that pins the behaviour down.

    aA lost response does not create a duplicate

    If Jira creates the issue but the response never arrives, the next run finds the issue by its risk-R-NNN label and updates it instead of creating another.

    test_lost_create_response_does_not_duplicate

    bCreates are not retried on 5xx

    Reads and updates retry on 429 (honouring Retry-After) and 5xx, at most five attempts. A create is not retried on 5xx, because a server error after the write would turn one issue into two. Found in review; two tests added.

    test_create_is_not_retried_on_5xx · test_429_retry_after_then_success

    cDone means the status category

    Jira returns status names in the user’s interface language; the live site answered “Backlog”, “Devam Ediyor”, “Tamam”. Overdue logic reads the status category (done), so a name check that would have silently broken was never written.

    test_overdue_logic_uses_status_category

    dPagination cannot loop forever

    Search uses POST /rest/api/3/search/jql with nextPageToken. Community reports describe the token repeating; the client stops with an error when a token or an issue key repeats, or after a page cap.

    test_search_repeating_token_is_an_error · …_repeating_issue_…

    eConflicts are skipped, orphans are left alone

    Two issues with the same risk label: the risk is skipped and the run exits 1. An issue whose risk is gone from the register is reported and never closed or deleted.

    test_duplicate_label_is_conflict_skipped_exit_1 · test_orphan_reported_and_untouched

    fThe token never reaches a log

    Credentials come from environment variables or a file outside the repo. Error messages, connection errors and the audit file are tested for the token string.

    test_token_never_in_error_text · test_token_not_in_connection_error

    How it was built

    The contract came first: DESIGN.md fixes field ownership, identity, the ten validation rules, the report and the audit format before any code. Behaviour that differs from it is a bug. Built with AI assistance and reviewed by a human; the live run was done by hand against a real Jira Cloud site.
